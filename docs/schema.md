# The CUE schema in a project

ANG's CUE schema (`cue/schema` in this repository: `#Operation`, the
`#FlowStep` union, `#Helpers`, `#Index`, `#Schedules`, the flow helpers …) is
what `cue vet`, editors and agents check a project's CUE against. A project
imports it as

```cue
import "github.com/strogmv/ang/cue/schema"
```

and never keeps its own copy: the copy is **vendored** from the ang binary
into `cue.mod/pkg/github.com/strogmv/ang/cue/schema/`, where CUE resolves
that import (like Go's `vendor/`). The binary embeds the schema of its own
revision, and `ang build` runs the revision the project's `ang.lock` pins, so
the vendored schema is always the one of the pinned ANG.

| Command | What it does with `cue.mod/pkg/github.com/strogmv/ang/cue/schema` |
|---|---|
| `ang build` | writes it when it differs (before generating) |
| `ang build --dry-run` | compares, warns `SCHEMA_STALE`, writes nothing |
| `ang build --check` | lists each differing file (`+`/`~`/`-`) and fails |
| `ang validate` | `SCHEMA_STALE` error (a warning when the binary is not the pinned revision) |
| `ang schema sync [project]` | writes it (also for a project that imports nothing yet) |
| `ang schema check [project]` | exits 1 when it differs; `--json` for tools |
| `ang init` | vendors it into the new project |

`ang schema sync|check` run the pinned toolchain like `ang build` (they refuse
another revision unless `--allow-lock-mismatch` or `ANG_TOOLCHAIN=local`).

The directory belongs to ANG: every file starts with
`// Code generated by ang … DO NOT EDIT.`, a file ANG does not ship is
removed, a hand edit is undone by the next build and fails `--check` until
then. Commit it with the rest of the generated code. A build vendors only for a
project whose CUE (under the cue root) imports the schema or that already has
the directory; projects inside ANG's own module (`examples/blog`) import the
repository's `cue/schema` and vendor nothing.

## A project's own definitions

Definitions only one project needs (dealingi-back's `#NotificationType`)
live in the project's own packages, next to their users — for example
`cue/events` — never in the vendored directory. A definition every project
could use belongs in ANG's `cue/schema`: add it there, then bump `ang.lock`.

## Moving from a copy in `cue/schema`

Projects used to copy the schema into their own `cue/schema` and import it as
`<module>/cue/schema`. `ang validate` reports such a copy as
`SCHEMA_PROJECT_COPY` (a warning). To move:

1. `ang schema sync`.
2. Replace the import `"<module>/cue/schema"` with
   `"github.com/strogmv/ang/cue/schema"` in every `.cue` file.
3. Move the project's own definitions out of `cue/schema` (see above).
4. Delete `cue/schema`; `ang validate` and `ang build --dry-run` must show
   the same generated files as before.

The build loads `#Codegen` (the type mapping in `codegen.cue`) from the
project's `cue/schema` while it exists, else from the vendored directory.
