# ANG Frontend SDK

Generated by `ang build`. **Do not edit** — change CUE intent and rebuild.

## Canonical data fetching (TanStack Query v5)

| API | Role |
|-----|------|
| `queryKeys.endpoint.<Service>.<Rpc>(params)` | Stable query keys: `['Service','Rpc', params]` |
| `endpointQueryOptions.<rpc>(params)` | `queryOptions({ queryKey, queryFn, … })` for every GET |
| `hooks/index.ts` `use<Rpc>()` | Spreads `endpointQueryOptions` only (no legacy resource keys) |
| `queries/index.ts` | `*QueryOptions` / infinite helpers using the same keys |

### Cache profiles (GET endpoints)

Set in intent metadata (any of these resolve to the same profile name):

- `frontend.queryProfile`, `queryProfile`
- `cacheProfile`, `frontend.cacheProfile`
- `client.query.profile`

Built-in profiles are listed in `queryProfiles` in `query-options.ts` (e.g. `realtime`: `staleTime: 0`, refetch tuning).

### WebSocket → query invalidation

See `hooks/websocket-hooks.ts`.

- **`defaultWsInvalidatePrefixes`**: service-level prefixes `['ServiceName']` for each service that has a GET (used when an event type has **no** explicit rule).
- **Per event** (from intent): if the event has `owner`, `consumers` (filtered to services with GET), or `frontend.ws.*`, a **narrow** rule is emitted instead of falling back to the default for that type.
- **Metadata** (under `frontend.ws`):
  - `invalidateRPCs: ["ListPosts", "GetPost"]` — invalidate `['Service','Rpc']` for each **existing** GET RPC
  - `invalidateServices: ["Blog"]` — `['Blog']`
  - `invalidateAll: true` — all services that expose GET (broad)
  - `noop: true` — no invalidation for this event type

### Extension layers

| Path | Purpose |
|------|---------|
| `adapters/index.ts` | DTO → view-model mappers (you implement) |
| `app-hooks/index.ts` | Re-exports `hooks`; add UI-facing aliases (`useMessengerChats`, …) |

### `queries/keys.ts`

Re-exports `queryKeys` from `./query-keys` — single source of truth.
